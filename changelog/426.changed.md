`permutation_shap()` takes the training data as the keyword argument `background` and samples `n_background` rows from it. The defaults are now 100 background rows and 2 permutations, which cost the same as 20 rows and 10 permutations and give smaller errors.
Requests have at most 50,000 rows by default, which uses fewer tokens, and at most 10,000 rows for a model fitted with `fit_mode="fit_with_cache"`, which the API rejects above that. `permutation_shap()` warns for such a model, because it needs more requests and runs slower.
