`api_mode` now also applies to `predict()`: with `"auto"`, the default, a prediction runs as a background job that the client polls once the training rows of the fit or the rows to predict reach thresholds that the server sets, while a fit with `fit_mode="fit_with_cache"` still predicts with one request. A prediction that takes longer than the server waits on one request no longer fails: the client polls for its result. `TabPFNClassifier` and `TabPFNRegressor` gained `submit_predict()`, which starts a prediction as a background job without waiting for it, and `wait_for_predict()`, which waits for it and returns what `predict()` returns, or `predict_proba()` for `output_type="probas"`. Two new errors, both `RuntimeError`s: `PredictFailedError`, raised when the server reports that a prediction it created failed, and its subclass `RefitRequiredError`, raised instead of a plain `RuntimeError` when the fitted model can no longer predict: call `fit()` again. A thinking-mode fit now always runs as a background job, whatever `api_mode` is, instead of keeping one request open for up to an hour. If `fit()` stops waiting for a background fit, after `TABPFN_CLIENT_ASYNC_POLL_TIMEOUT` seconds (by default the server's 2 hours) or an interrupt, the model is pending on the new fit, which `wait_for_fit()` resumes and `save_model()` saves; a fit that the server reports as failed leaves the model unfitted. A regressor's `"full"` output that is split over several requests keeps up to 4 of them running at once as background jobs. `fit()` and `predict()` no longer resend a request that the server may already have received, for example after a lost response or an HTTP 503, which could fit or predict, and bill, twice: they retry only a request that never reached the server.
